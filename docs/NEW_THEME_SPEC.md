# 1. Концепция нового сайта

## Позиционирование

Новый сайт — не «каталог компании», а цифровой интерфейс производственного партнёра. Посетитель за 10–15 секунд должен понять:

1. какие технологические задачи можно передать компании;
2. работает ли компания с его типом изделия и объёмом партии;
3. какие исходные данные нужны для расчёта;
4. как отправить чертёж и получить консультацию.

Рабочая формула первого экрана: **«Производственные операции и гидравлические решения по чертежу, 3D-модели или образцу»**. Фактическую географию, парк оборудования, диапазоны размеров, точности, материалы, сроки, сертификаты и объёмы партий публиковать только после подтверждения; до этого использовать `[уточнить]`.

## Визуальная идея: Precision Lime

- **Образ:** тёмная инженерная среда, крупная типографика, светлые технические плоскости и салатовый сигнал действия.
- **Ассоциации:** металл, координатная сетка, измерение, маршрут операции, контрольная отметка, рабочая документация.
- **Не использовать:** клише с шестернями, чрезмерный «киберпанк», тяжёлые 3D-сцены, бесконечные карусели, стоковые рукопожатия, неподтверждённые счётчики.
- **Фото:** реальные процессы, детали крупным планом, оборудование и контроль. Для каждого изображения фиксировать авторство, контекст, alt и разрешение. До получения фотографий — нейтральные геометрические placeholders с маркировкой `[заменить фото]`.
- **Графика:** тонкие размерные линии, номера операций, метки материала, условные схемы детали. Они декоративны и не должны выглядеть как реальные допуски.

## Поведение интерфейса

- Спокойные появления на 8–16 px и 160–240 мс только при наличии `prefers-reduced-motion: no-preference`.
- Hover карточки: подъём не более 2 px, усиление границы, проявление CTA; контент не прыгает.
- Sticky header становится компактнее после первого экрана; на мобильном — простое полноэкранное меню без сложных вложенных жестов.
- Никакой обязательной горизонтальной прокрутки для чтения. Горизонтальный rail услуг — progressive enhancement, а не единственный способ доступа.
- Формы показывают ошибки рядом с полями и общий статус; состояние не кодируется одним цветом.

# 2. Лучшее решение для главной страницы

## Варианты показа услуг

| Вариант | Как работает | Плюсы | Риски |
|---|---|---|---|
| Карточная сетка 2×5 | Все услуги видны сразу | SEO, доступность, предсказуемость | Длинный блок, слабее разделение направлений |
| Горизонтальный rail | Крупные визуальные карточки листаются | Премиальная подача, хороший storytelling | Часть услуг скрыта, неудобно с клавиатуры без тщательной реализации |
| Табы + сетка | Фильтры «Металлообработка / Гидравлика / Сварка и покрытия / Контроль» и карточки | Быстрый выбор, масштабируется, все ссылки остаются в DOM | Нужно ясно показать количество и не скрывать контент от поисковика |

## Выбор: гибрид «направления + интерактивная сетка»

На desktop: слева sticky-заголовок и фильтры направлений, справа — асимметричная сетка из 10 карточек. На mobile: обычный список карточек и горизонтальная строка фильтров. Фильтры меняют визуальную видимость, но все ссылки присутствуют в HTML; без JavaScript показываются все услуги. Первая карточка каждого направления может быть крупнее, если есть качественное фото.

Почему это лучше: посетитель видит широту компетенций, быстро сужает выбор и всегда может открыть отдельную посадочную. Слайдер допустим только для кейсов, где последовательный просмотр естественен.

### Требования к hero

- Один H1, не более 10–14 слов в основной строке.
- Primary CTA: «Отправить задачу»; secondary: «Выбрать услугу».
- Три тезиса только фактические: «По чертежу, модели или образцу» допустим, если процесс подтверждён; материалы/точности/сроки — `[уточнить]`.
- На mobile не загружать тяжёлое hero-video; использовать responsive poster.

# 4. Посадочные страницы услуг

## Единый каркас страницы услуги

1. Breadcrumbs.
2. Hero: группа услуги, H1, краткое УТП, primary CTA, фото/схема.
3. «Что выполняем»: объяснение и типовые задачи.
4. «Кому подходит»: отрасли и сценарии.
5. «Технические возможности»: таблица только с подтверждёнными параметрами.
6. «Материалы и изделия»: списки с оговорками.
7. «Как проходит заказ»: 4–6 этапов.
8. «Контроль качества»: контрольные точки и доступные документы `[уточнить]`.
9. Кейсы, связанные по услуге.
10. Преимущества именно этой технологии, без повторения общих лозунгов.
11. FAQ (видимый текст и синхронный JSON-LD).
12. Связанные услуги и финальный CTA.

# 6. WordPress-архитектура

## Принцип миграции

Не переписывать рабочую тему одним релизом. Новые CPT, поля и компоненты добавлять совместимо; сначала staging, затем импорт контента и переключение шаблонов. Существующие URL инвентаризировать до изменения permalink. Редиректы утверждать отдельно.

## Модель контента

| Сущность | Реализация | Ключевые поля |
|---|---|---|
| Услуга | CPT `service`, rewrite `uslugi`, archive | hero lead, short card text, group, image, capabilities, materials, process, quality, CTA, related services |
| Кейс | CPT `case_study`, rewrite `raboty` | задача, исходные данные, маршрут, результат, gallery, связанные услуги/отрасли; все цифры `[уточнить]` |
| Оборудование | CPT `equipment` или options/repeater при <5 записей | назначение, процессы, подтверждённые параметры, media, related services |
| FAQ | Repeater на услуге для малого объёма; отдельная сущность только при повторном использовании | question, answer, порядок; schema выводится из тех же данных |
| Отрасль | taxonomy `industry` для service/case | name, description, image; публичный archive только при уникальном контенте |
| Группа услуг | taxonomy `service_group` | title, nav order, accent marker |
| Глобальные данные | ACF Options или Settings API | контакты, legal links, social, CTA defaults, organization schema |

### Где регистрировать CPT

Регистрацию CPT и таксономий лучше вынести в небольшой functionality-plugin `kelrnand-core`, чтобы URL и данные не зависели от активной темы. Если инфраструктура пока деплоит только тему, допустим временный `inc/post-types.php`, но в плане миграции зафиксировать перенос в plugin до наполнения production.

### ACF

- ACF Pro уместен, если лицензия подтверждена `[уточнить]`; иначе Carbon Fields/Meta Box либо core meta APIs.
- Field groups хранить в `acf-json/` и коммитить.
- Ограничивать layouts и количество элементов: редактор меняет данные, а не произвольную геометрию.
- Не хранить критичный текст только в options, если ему нужен отдельный URL и revision history.
- Экранировать значения при выводе, разрешённый rich text пропускать через `wp_kses_post()`.

## Компонентный подход

`get_template_part( 'template-parts/components/card', 'service', $args )` для небольших компонентов; секции получают нормализованный `$args`, не читают хаотично глобальные поля. Для сложных блоков создать view models в `inc/template-data.php`. Компоненты должны иметь безопасные defaults и не выводить пустые wrappers.

## JavaScript

Vanilla ES modules или один небольшой bundle. JS нужен для меню, фильтра услуг, accessible disclosure/FAQ, controlled slider кейсов и улучшения формы. Без JS все ссылки, карточки и FAQ доступны; Swiper подключать только если нативный scroll-snap не покрывает задачу.

# 8. Дизайн-система

## Токены

| Категория | Значения |
|---|---|
| Ink | `#101820` основной тёмный, `#17242E` raised dark |
| Paper | `#F7F9F8`, pure `#FFFFFF` |
| Lime | `#B7F34A` action background, `#8FD11F` hover, `#497A0A` текстовая ссылка на светлом фоне |
| Steel | `#60717D`, `#9BA9B2`, `#D8E0E3` |
| Status | success `#18794E`, warning `#9A6700`, danger `#B42318`; не заменять статусные цвета lime |
| Шрифт | локально размещённый variable grotesk `[выбрать/лицензия уточнить]`; fallback `Inter, system-ui, sans-serif`; для параметров — tabular numerals |

Контраст текста: WCAG 2.2 AA, минимум 4.5:1 для обычного текста и 3:1 для крупного. Яркий lime не использовать как мелкий текст на белом — применять тёмный lime token.

## Типографика

- Display: `clamp(2.75rem, 6vw, 6.5rem)`, line-height 0.95–1.02, letter-spacing −0.04em.
- H1 внутренних страниц: `clamp(2.5rem, 5vw, 5rem)`.
- H2: `clamp(2rem, 3.6vw, 3.75rem)`.
- H3: `clamp(1.25rem, 2vw, 1.75rem)`.
- Body L: 1.125rem/1.65; body: 1rem/1.65; meta: 0.75–0.875rem, uppercase только для коротких labels.
- Длина строки основного текста 60–75 символов.

## Пространство и сетка

- Spacing: 4, 8, 12, 16, 24, 32, 48, 64, 96, 128 px; в CSS через fluid `clamp()` для section space.
- Container max 1440 px, content max 1200–1280 px, gutters 20/32/48 px.
- Desktop 12 колонок, tablet 8, mobile 4; gap 16–24 px.
- Breakpoints ориентировочно 480, 768, 1024, 1280, 1536; компоненты по возможности через container queries.

## Компоненты

- **Primary button:** lime background, ink text, 48–56 px, radius 6 px; hover темнее, active translateY(1px), focus ring 3 px с offset.
- **Secondary:** transparent, контрастная border; text link имеет видимое подчёркивание или стрелку, не только цвет.
- **Cards:** radius 8–12 px, 1 px steel border; тени только на overlay/hover (`0 16px 50px rgb(16 24 32 / 10%)`).
- **Forms:** label всегда видим; control ≥48 px; required обозначается текстом/символом; error связан через `aria-describedby`; file upload показывает тип/лимит.
- **Tables:** sticky first column только при необходимости, mobile scroll wrapper с понятной подсказкой; caption обязателен для технических параметров.
- **Badges:** нейтральные для категорий, lime только для действия/активного фильтра.
- **Slider:** кнопки previous/next, counter, pause для autoplay; autoplay по умолчанию не нужен.
- **Icons:** единый outline set 1.5–2 px, SVG inline с `aria-hidden` для декоративных; не использовать emoji как production icons.

# 12. План поэтапного внедрения

| Этап | Объём | Результат | Rollback |
|---|---|---|---|
| 0. Discovery | URL/content/infra audit, подтверждение данных | Инвентарь и acceptance criteria | Нет production changes |
| 1. Foundation | tokens, component folders, build, header/footer за feature flag | Новый каркас на staging | Отключить flag/revert assets |
| 2. Content model | CPT/taxonomies/fields, seed services | Данные доступны в WP с revisions | Старый массив остаётся fallback временно |
| 3. Service templates | archive + single + schema + FAQ | 10 landing pages на staging | Не публиковать CPT/вернуть templates |
| 4. New home | все секции и dynamic content | Новая главная на staging | Вернуть старый `front-page.php` |
| 5. Cases/equipment | CPT views и связи | Trust/content layer | Скрыть пустые archives |
| 6. Forms/SEO | CRM/SMTP, consent, metadata, redirects | Готовность к индексации и лидам | Direct contacts + previous form |
| 7. QA/launch | performance/a11y/content/UAT | Controlled production release | Revert merge commit/redeploy prior release |
| 8. Growth | industries, knowledge base, experiments | SEO expansion based on evidence | Independent feature releases |

Каждый этап — отдельный PR. Не удалять старые templates и массив услуг, пока новые данные не импортированы, URL не проверены, а rollback не протестирован.
