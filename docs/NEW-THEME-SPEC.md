# Концепция новой темы ZUB Industrial

> Статус: техническая и контентная спецификация. Все значения, которые требуют подтверждения владельцем сайта, отмечены как **[уточнить]**. Документ не является заявлением о фактическом составе оборудования, допусках, сертификатах, сроках или ценах.

## 1. Концепция нового сайта

### Позиционирование

Сайт должен восприниматься не как каталог цеха, а как цифровой интерфейс производственного партнёра: задача заказчика переводится в технологический маршрут, проходит производство и завершается контролируемым результатом. Основная идея интерфейса — **«точность, видимая в деталях»**.

* **Характер:** строгий, инженерный, спокойный, без декоративного «техно» и необоснованных обещаний.
* **Композиция:** крупная типографика, асимметричные поля, модульная 12-колоночная сетка, тонкие технические линии и номера секций.
* **Визуальный язык:** реальные крупные планы операций, деталей, кромок, швов и измерений; поверх фотографий допустимы лаконичные размерные линии и подписи параметров.
* **Тон:** конкретный B2B-язык — входные данные, операция, контроль, результат. Любые цифры публикуются только после проверки.
* **Антипаттерны:** стоковые люди в касках, фоновые шестерёнки, карусель в первом экране, автозапуск видео со звуком, счётчики с неподтверждёнными цифрами, бесконечные параллаксы.

### Визуальная система

Основной фон — тёмный графитово-синий `#101C27`, рабочие поверхности — белый и холодный серый `#F1F4F5`, сигнальный акцент — технологичный лайм `#A3E635`. Акцент используется дозированно: CTA, активное состояние, маркер контроля. Фотографии получают холодную нейтральную цветокоррекцию, но изделие и цвет покрытия не искажаются.

Заголовки — современный гротеск **Manrope** или локально размещённый **Onest**; текст — **Inter** либо системный стек. До появления юридически проверенных лицензий шрифтов безопасный вариант — `system-ui`. Числа и технические параметры желательно выводить табличными цифрами.

### Движение и поведение

* Появление секций: opacity + translateY до 16 px, 240–360 мс, только при наличии Intersection Observer.
* Hover карточки: подъём на 2–3 px, усиление границы и появление стрелки; карточка остаётся понятной без hover.
* Горизонтальный список услуг на desktop управляется кнопками и колесом, на mobile — нативным scroll-snap. Контент не должен зависеть от JS.
* Для `prefers-reduced-motion: reduce` отключаются smooth scroll и все необязательные переходы.
* Sticky-header сохраняет быстрый CTA, но не занимает более 76 px на desktop и 64 px на mobile.

## 2. Лучшее решение для главной страницы

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| Сетка 2×5 | Все 10 услуг видимы, хорошо сканируется и индексируется | Длинный блок, слабее ощущение продукта | Хороший fallback |
| Горизонтальный scroll-snap | Выразительная подача, крупный визуал | Часть услуг скрыта; нужна заметная навигация | Использовать только как enhancement |
| Табы по направлениям + карточки | Быстро сужает выбор, сохраняет обзор и SEO-контент | Требует корректной работы без JS | **Рекомендуется** |

Лучшее решение — гибрид: четыре фильтра **Все / Металлообработка / Гидравлика / Сварка и покрытия / Испытания** и доступная сетка карточек. На desktop показывать первые 6 карточек и явную кнопку «Все услуги», на mobile — все карточки либо нативный scroll-snap. Фильтрация прогрессивная: без JavaScript все услуги видимы. Клик по карточке ведёт на посадочную, вторичный CTA сразу переносит название услуги в форму.

## 4. Посадочные страницы услуг

### Единый каркас

1. Breadcrumbs и hero: категория, H1, краткое УТП, CTA, релевантный визуал.
2. «Что делаем»: 2–3 абзаца без воды.
3. «Кому подходит / какие задачи решает»: две колонки.
4. «Технические возможности»: проверяемая таблица параметров; неизвестное — **[уточнить]**.
5. «Материалы и типовые изделия».
6. «Как выполняется заказ»: входные данные → подготовка → операция → контроль → передача.
7. «Контроль качества»: методы и выдаваемые документы **[уточнить]**.
8. Преимущества процесса, связанные оборудование и кейсы.
9. FAQ (4–6 действительно полезных вопросов).
10. Финальный CTA и короткая форма с предвыбранной услугой.

Desktop: логотип; мегаменю «Услуги» в четыре группы; «Возможности», «Работы», «Качество», «О компании», «Контакты»; справа CTA «Отправить чертёж». Mobile: полноэкранная панель, раскрываемый список услуг, видимые телефон/email **[уточнить]**, закреплённая нижняя кнопка CTA. Footer: услуги по группам, компания, материалы, документы, контакты. Быстрые CTA: «Рассчитать заказ», «Отправить чертёж», на мобильном дополнительно `tel:` только после добавления реального номера.

База знаний уместна после формирования редакционного плана: требования к файлам, выбор технологии, подготовка чертежа, особенности покрытий. Не запускать пустой блог ради SEO.

## 6. WordPress-архитектура

Рекомендуется гибридная component-based classic theme: PHP-шаблоны задают жёсткую систему, Gutenberg редактирует безопасные текстовые области, структурированные сущности хранятся в CPT. Регистрацию CPT лучше вынести в небольшой functionality plugin, чтобы контент не исчезал из admin при смене темы.

| Сущность | Хранение | Ключевые поля |
|---|---|---|
| Услуга | CPT `service`, taxonomy `service_category` | short_offer, card_text, hero_media, audience, tasks, capabilities repeater, materials, process, quality, CTA, FAQ relation |
| Кейс | CPT `case`, taxonomies `industry`, `technology` | challenge, source_data, route, result, gallery, service relations; все цифры требуют подтверждения |
| Оборудование | CPT `equipment`, taxonomy `equipment_type` | model **[уточнить]**, verified specs repeater, photo, service relations |
| FAQ | Repeater внутри услуги для простоты; отдельный CPT только при массовом переиспользовании | question, answer, schema_enabled |
| Настройки | ACF Options или core options с capability checks | контакты, реквизиты, формы, social, default CTA |

ACF Pro допустим, если лицензия подтверждена. Field groups сохранять в `acf-json/`; обязательные поля помечать, инструкции показывать рядом; числа не подставлять по умолчанию. Для редакторов использовать ограниченные patterns, `template_lock: contentOnly`, preview и sanitization. Дизайн нельзя собирать произвольными отступами и цветами в редакторе.

Переиспользуемые компоненты: `section-heading`, `service-card`, `case-card`, `spec-table`, `process-steps`, `quality-list`, `faq`, `contact-form`, breadcrumbs и CTA-band. Каждый получает массив данных, экранирует вывод на последнем этапе и работает без JavaScript.

Schema: `Service` на посадочной, `BreadcrumbList`, `Organization` только с реальными реквизитами, `FAQPage` только для видимых вопросов. Перед выводом проверять, не генерирует ли те же сущности SEO-плагин.

Кнопки имеют высоту не менее 48 px; primary — лайм на navy-тексте, secondary — прозрачная с контрастной границей, text-link — со стрелкой. Формы используют видимые labels, подсказки и inline error, `:focus-visible` толщиной 2 px. Минимум WCAG 2.2 AA: контраст 4.5:1 для обычного текста, клавиатурный доступ, skip-link, логичный focus order, цели касания 44×44 px, ошибки не только цветом, alt описывает смысл, не внешний вид.

| Полуавтомат | полуавтоматическая сварка металла | мелкосерийная сварка, сварные конструкции |
| Испытания | испытание гидравлического оборудования | лаборатория, стенд, проверка гидроцилиндров/РВД |

Одна посадочная — один основной интент. H1 используется один раз; H2: возможности, изделия, процесс, контроль, примеры, FAQ; H3 — конкретные методы, этапы и карточки. Title 50–65 символов ориентировочно, description 120–160, но важнее ясность и отсутствие дублей. Регион добавлять только после подтверждения фактической географии.

Перелинковка: услуга → связанное оборудование, 2 кейса, соседняя технология и контроль качества; кейс → применённые услуги; статья → релевантная услуга и CTA; breadcrumbs на всех внутренних страницах. Архив услуг индексируемый и содержит вводный текст, категории и уникальные карточки. Теги без полезного наполнения закрыть от индексации.

Коммерческое доверие формируют не лозунги, а: реальные фото; проверенные возможности; понятные входные данные; этапы контроля; образцы документации с закрытыми данными **[уточнить]**; реквизиты и адрес **[уточнить]**; кейсы с разрешением клиента **[уточнить]**. Не публиковать логотипы, сертификаты и отзывы без разрешения.

Скорость: AVIF/WebP с `srcset`, размеры изображения в HTML, lazy-load ниже fold, preload только hero, локальные subset-шрифты, критический CSS по необходимости, JS defer и разбивка по функциям, отсутствие jQuery-зависимости, кэш страниц/CDN **[уточнить]**. Цели: LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1 на реальном mobile p75.

## 11. Техническое задание для Codex

### Цель

Пошагово преобразовать текущую Git-first classic theme в компонентную промышленную тему, сохранив рабочий деплой и обратную совместимость. На первом релизе внешний контент остаётся доступным, формы и URL не ломаются; новые сущности включаются после staging-проверки и наполнения.

### Практическая последовательность

1. Создать ветку `feature/component-theme-v2`; зафиксировать текущие URL, меню, настройки чтения, плагины SEO/forms/cache и сделать backup **вне Git**.
2. Не менять `.github/workflows/deploy.yml` без отдельной задачи. Проверить точную deployment branch и удалённую папку темы. Не коммитить `.env`, дамп БД, ключи и uploads.
3. Разнести bootstrap: `inc/setup.php`, `enqueue.php`, `schema.php`, `forms.php`, `breadcrumbs.php`. В `functions.php` оставить константы и `require_once`. Все функции префиксовать `zub_`; классы/хуки документировать.
4. Вынести секции `front-page.php` в перечисленные `template-parts`. Использовать `get_template_part( ..., null, $args )`; каждый partial проверяет типы и экранирует `esc_html`, `esc_url`, `wp_kses_post` по контексту.
5. Реализовать архив и single услуги. До миграции сохранить массив `inc/services.php` как fallback. Не переключать карточки на новые URL, пока соответствующие страницы не опубликованы.
6. Зарегистрировать `service`, `case`, `equipment` и таксономии в functionality plugin либо документировать зависимость. Включить `show_in_rest`, понятные labels, revisions, thumbnails; после регистрации один раз обновить permalinks через admin, не вызывать `flush_rewrite_rules()` на каждом запросе.
7. Добавить ACF field groups и `acf-json` только после подтверждения ACF Pro. При отсутствии ACF шаблоны должны показывать fallback или скрывать пустой блок без PHP warning.
8. Собрать главную: hero, УТП, фильтруемая сетка 10 услуг, возможности, отрасли, кейсы, качество, процесс, преимущества, CTA и форма. Фильтры работают как enhancement: весь контент доступен без JS.
9. Собрать `single-service.php` по единому каркасу; таблица характеристик выводит только заполненные поля; связанные кейсы/оборудование ограничить 3 элементами; FAQ видим до генерации schema.
10. Перенести CSS к токенам и компонентным слоям. Не подключать Bootstrap, Tailwind runtime, slider library или animation framework. Минифицировать production asset; сохранить readable source.
11. Улучшить navigation JS: Escape закрывает меню, focus возвращается в toggle, переход через breakpoint очищает состояние. Добавить focus trap только для действительно модальной mobile panel.
12. Форму обрабатывать через nonce, honeypot, rate limiting **[определить на инфраструктуре]**, server-side validation и sanitization. Для файлов задать allowlist MIME/extension, размер **[уточнить]**, случайное имя и политику удаления. Не логировать персональные данные. SMTP/CRM подключать адаптером **[уточнить]**.
13. SEO: title-tag через core/SEO plugin; canonical и sitemap не дублировать; JSON-LD кодировать `wp_json_encode`; Service/FAQ/Breadcrumb выводить только на соответствующей странице и только из видимого контента.
14. Миграция: создать сущности на staging, импортировать 10 услуг, сопоставить slug, проверить 301 только если URL изменился. Старые anchors сохранить минимум на переходный период.
